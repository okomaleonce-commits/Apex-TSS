APEX-DIGEST

Une requête — une date, une période, un match, une ligue, une liste — traversée par tous les moteurs, en un seul digest. Cette page compose la commande ; l'analyse tourne en session.

Gel actif.Aucune mise réelle n'est émise. Donnée absente d'un jour = écrite absente, jamais simulée.

Composer la requête

Choisir le type de requête, le(s) sport(s), puis remplir les champs. La commande se met à jour en continu.

Type de requête
Sports (chaîne par sport)

Commande à lancer en session

Lancer dans le dépôt, puis envoyer le digest par email (connecteur Gmail) — un passage APEX sans email est incomplet. Sorties dans reports/digest/.

Ce que produit chaque moteur

Football

Mécanisé de bout en bout. Jour entier → digest FUSION canonique ; match / ligue / liste / période → carte ORION focalisée ; un match nommé reçoit le détail BSM (simulation Monte-Carlo cachée).

WORM → MI → BSM → FUSION/ORION → sources sharp

Turf

Digest APEX-TURF-WORM du jour, lu depuis le snapshot. Palier maximal SURVEILLER (gates de pari fermées par le backtest). Sans passage exploitable : la commande de scan est indiquée, rien n'est simulé.

TURF-WORM → TURF-MI (bruit) · périmètre LONACI

Hockey

La chaîne hockey est pilotée par apex_hockey_lead depuis un fichier d'entrée. Le dispatcher résout la requête en un scaffold d'input prêt à lancer — aucune analyse n'est fabriquée.

DISCOVERY → G0…G7 (init → check → finalize)

Après la commande

  1. 1Lancer la commande dans le dépôt (lecture seule ; relancer un scan si le snapshot du jour manque).
  2. 2Le digest unifié s'écrit dans reports/digest/<slug>.html (+ .txt, .subject.txt).
  3. 3Envoyer ce digest par email via le connecteur Gmail à okoma.leonce@gmail.com.
  4. 4Après les matchs : apex_postmatch.py run boucle settle → CLV → calibration.

Tous les gates restent en vigueur : EV robuste ≥ 3 %, sensibilité, veto J27 (ROI de ligue négatif), moins de 3 voix indépendantes → COLLECTER. ORION peut toujours décider de ne rien faire.
